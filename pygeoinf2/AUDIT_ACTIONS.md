# Acting on the functionality audit

One line per item from `FUNCTIONALITY_AUDIT.md` §0.2–§0.4, worked through one
at a time: one item, one session, one commit. Each line ends in a verdict —
**restored**, **subsumed** (how), **dropped** (why), or **not a defect** — with
the commit that settled it. Pick the next unticked line rather than re-reading
the audit; the per-symbol evidence is in its §2–§3 tables.

Baseline on 2026-09-16: 2454 passing in the fast suite.

## 1. Correctness claims (§0.3, "changed numerics")

- [x] `with_regularized_inverse`: covariance and precision disagree for `damping > 0` — **dropped**. The mismatch was real (the mixture density it fed raised), but its one use was a damped `Q⁻¹` for the Woodbury data form, which is now `WoodburyPreconditioner(prior_damping=)`. DESIGN §36.
- [x] `WoodburyPreconditioner.data_form()` on a Tikhonov operator returns `t·N⁻¹` not `N⁻¹` — **restored**, and wider than the audit saw: every factor-built preconditioner had the factor. `FactoredNormalOperator.scale` now carries it and each consumer divides by it. DESIGN §37.
- [x] adjoint solve of a non-self-adjoint operator with a fixed preconditioner uses `P` not `P*` — **restored**: iterative inverses now carry an adjoint solve preconditioned by `P*` from the same resolved `P`, which also ends the second factorisation of a deferred direct preconditioner. Right answer, slow, before; never a wrong number. DESIGN §38.
- [x] `operator_log` has no floor on Ritz values — **restored**, generalised: both Lanczos kernels now hold Ritz values to the claimed spectrum (floor at 0 for semidefinite, `eps·λmax` for definite), and refuse a meaningfully negative one as a false claim. Triggered by formed `L L*` covariances, which also broke `sqrt` and fractional powers and every stochastic log-determinant. DESIGN §39.
- [x] CG lost its non-finite breakdown checks — **restored**, and for every iterative solver: a non-finite residual is refused at once in the shared per-step hook, regardless of `strict`; CG also refuses `(r, P r) <= 0`. Before, a NaN ran to the iteration cap (800 applications at dim 400) and under `strict=False` came back as a NaN answer. DESIGN §40.
- [x] `apply_operator_function` caps at 50 iterations with `rtol=1e-10` — **restored** v1's dimension cap and kept v2's tolerance: measured, the cap of 50 never let the tolerance be met (50 applications always; 1e-3 to 1e-1 error on hard spectra, silently), v1's `1e-3` delivered 1e-2, and `1e-8` delivered 1e-6. Same for the quadratic form and `OperatorFunction`. DESIGN §41.
- [x] path operators bypass the Sobolev-order guard — **restored**, with the right threshold: a path integral needs order above `(d-1)/2` (one half on a surface, measured: the representer diverges at and below it), not point evaluation's `d/2` that v1 used; `unsafe=True` on both path methods. Ball averages need no order and keep their bypass. DESIGN §42.
- [x] `StrongWolfeLineSearch._zoom` is pure bisection — **restored**: cubic/quadratic interpolation with bisection as the safeguard, as SciPy's search that v1 wrapped; the wasted re-evaluation on zoom entry is gone. Nonlinear CG halves its evaluations (224→113 Rosenbrock, 4321→2013 on a cond-1e4 quadratic), same answers. DESIGN §43.
- [x] `LevelBundleMethod`: serious/null step test, QP warm start, λ bounding box — **restored** all three, plus `lower_bound` and `serious_steps` on the result. DESIGN §44.
- [x] `ProximalBundleMethod`: exact QP backend replaced by projected gradient with a residual floor — **restored**: the k-variable dual now goes through Clarabel or OSQP when installed (30× faster, 1000× closer to the primal on the Backus dual), projected gradient as the fallback; backend order now Clarabel first, OSQP having capped out on 40% of level masters. DESIGN §44.
- [x] v1's probed default adjoint versus v2's `NotImplementedError` — **subsumed** as an opt-in: `with_probed_adjoint()` assembles the matrix once and derives the adjoint from it; the refusal stays the default and its message names the opt-in. DESIGN §45.

## 3. Dense-by-default regressions (§0.3), in the audit's order of likely pain

Moved ahead of the lost capabilities on 2026-09-16: these bear directly on the
matrix-free aim and the audit ranks the first six as the ones most likely to
bite on a real problem; the small restorations below matter less in practice.

- [x] `with_sparse_approximation` forms the dense covariance first — **restored** as an operator: `numerics.sparse_approximation` probes columns matrix-free with v1's correlation criterion and cap, sharing the thresholded preconditioner's assembly; `GaussianMeasure.sparse_covariance` delegates; the measure-returning method is gone. DESIGN §47.
- [x] `nuclear_norm` / `hilbert_schmidt_norm` default dense; correlated invariant measures assemble the block matrix — **restored**: `auto` is exact and matrix-free (spectrum, spectral slices, stored matrix, or probed diagonal in linear memory); `dense` is opt-in. KL's refusal above `dense_limit` kept as D-8. DESIGN §48.
- [x] `credible_set` without a precision goes O(N³); `ambient_ball(method='auto')` picks dense `eigh` — credible set **restored** matrix-free: the precision is the covariance's inverse through a solver (CG by default, a direct solver by name); ambient ball **kept**, the dense route being cheaper than sampling at its limit and exact. DESIGN §49.
- [x] `FeasibleProperty.is_feasible` does a dense `eigh` — **restored** v1's matrix-free test: a damped minimum-norm root search in the data space, one warm-started Krylov solve per probe; the dual route uses it too when its sets are balls. Data spaces are small only relative to model spaces. DESIGN §50.
- [x] `l2_products_operator` stacks a dense matrix; low-rank factors stored as dense blocks — **not a defect** as stated (the rows and the column blocks are the vectors themselves, and smaller than the fields), but a real trap beside it **fixed**: a composition's known matrix multiplied low-rank factors into a dense n×n product for any caller that asked; it now declines a product larger than its largest factor and gives the diagonal of a low-rank product in O(nk). DESIGN §51.
- [x] `LinearGaussianInversion` factorises at construction; `normal_log_determinant` forms dense Galerkin matrices — construction **restored** lazy at the solver: every direct solver now factorises on first use and keeps the factors (v1 refactorised per call); the log-determinant's routing **kept**, it already counts applications. DESIGN §52.
- [x] `Ellipsoid.project` factorises the dense Galerkin matrix every Newton step — **fixed** (new in v2, no v1 path): the two solves per step go through `resolve_solver`, CG at 1e-12 by default with a first-order predictor as warm start; a direct solver by name as before. DESIGN §53.
- [x] `DiagonalMetricSpace.gram_matrix()` probes a dense array; `MassWeightedSpace.mass_inverse` defaults to CG — **restored**: the Gram matrix is `diag(metric_values)` written down, the dense log-determinant sums the diagonal's logs instead of a cubic `slogdet`, and a diagonal mass inverts exactly as its docstring promised. DESIGN §54. Group 3 closed.

## 4. Lost capabilities with an obvious home (§0.2)

- [x] 4. `SolutionTrackingCallback`: the solver callback cannot see the iterate — **restored**: every iterative solver hands its callback a `SolveStep` whose `iterate` is formed on demand (free where the solver holds it, assembled from the Arnoldi basis in GMRES only when asked) and returned as a copy; `SolutionTrackingCallback` keeps them in `iterates`. DESIGN §55.
- [x] 3. `HalfSpace` support function raises — **restored**: `SupportFunction.of_half_space` is extended-real valued (`alpha * offset` along the outward normal, `+inf` elsewhere, parallelism decided on the residual in the space's norm), its maximiser the boundary's least-norm point, `ValueError` in an unbounded direction; the hyperplane gets the two-sided version. DESIGN §56.
- [x] 2. `SublevelSet` / `LevelSet`, `is_empty`, `is_bounded`, `closure`, `boundary`, convexity `check` — sets **restored** (`geometry.sets.SublevelSet` / `LevelSet`, membership and boundary, from any `Functional`); `boundary` **restored** on the base as a property, with a refusal by default and answers on the trivial sets, complements, and every thin set; convexity check **subsumed** as `testing.check_convexity` on the functional; `is_empty`, `is_bounded`, `closure`, `is_open` **dropped** (no caller in v1; the first two were stubs, the last two belong to the open-set flag v2 does not have; emptiness of a feasible set is `FeasibleProperty.is_feasible`, DESIGN §50). DESIGN §57.
- [x] 17. `BackusInference` is a name reused for a different route — **resolved by redesign**: the three route classes are private engines inside one estimator, `BackusGilbertParker(problem, target, prior, noise=)`, which chooses the route from the sets (closed form for a ball prior and exact data, bisection for two balls, the dual otherwise) and takes `route=` to force one; the answer carries both the support function and, when the sets are balls, the membership test; `BackusInference` is retired (the naming pass may alias it in `compat`). DESIGN §58.
- [x] 16. `CallableSupportFunction.support_point` — **restored** as `SupportFunction.of_oracle(domain, value, maximiser=)`: a support function from callables, whose `has_subgradient` is true only with a maximiser; `ConvexSet.from_support_function` now hands its maximiser through to the functional it returns, where it was dropped. The fused `value_and_support_point` stays subsumed by the dual route's one-entry memo. DESIGN §61.
- [x] 14. affine-operator axiom checks in `testing.py` — **restored** as `testing.check_affine`: translation recovered at zero, affine combinations preserved, derivative equal to the linear part, then `check_operator` on the linear part (adjoint identity included, which v1 skipped). No `measure=` sampler yet; that goes with the knobs group for every check. DESIGN §62.
- [x] 12. public spectral indexing (`indices`, `index_to_integer`, …) — **restored**, vectorised: the sphere's `orders` (signed) beside `degrees`, the boxes' `wavevectors` and `phases`, and `component_of(label)` placing one label or an array of them; the reverse map and v1's `indices` are indexing and zipping the arrays; `coefficient_operator(components=)` and its synthesis companion then map a field to named coefficients and back, the application David named. No scalar wrappers, by decision. DESIGN §63.
- [x] 13. saddlepoint `weighted_chi2_cdf`, array thresholds, finite-difference dual gradient — saddlepoint **restored** as `method="saddlepoint"` (ten to a thousand times cheaper than Imhof, matches v1 to eight figures; `auto` stays on Imhof because the error follows the spectrum's shape, not v1's effective degrees of freedom); array thresholds **dropped** (no caller; map over a scalar); finite-difference dual gradient **dropped** on purpose (a maximiser is now asked for by name, §61, and central differences on a nonsmooth cost are not a subgradient). DESIGN §64.
- [x] 18. invariant-measure algebra loses its Karhunen–Loève sampler — **restored** on the structure, not the class: any measure whose factor is diagonal draws in one synthesis (white-noise components scaled by the eigenvalues), so scaled, summed, translated and marginal measures keep the draw with nothing carried; a diagonal covariance gets its square-root factor for any non-negative spectrum and its precision only for a positive one, so a sum touching a band limit keeps its factor; a marginal keeps its precision. The class itself stays a factory (David: the spectrum is `.covariance.eigenvalues`). DESIGN §65.
- [x] 5. `weakened_ellipsoid`, Cameron–Martin credible set, `sample_pointwise_variance`, KKT push-forward precision — weakened ellipsoid **restored** as `GaussianMeasure.weakened_ellipsoid(level=, power=)`, exact on a diagonal covariance and by the operator calculus otherwise, its ends the credible set and the ambient ball; sampled pointwise variance and std **restored** on any module domain; Cameron–Martin credible set **subsumed** by the credible ellipsoid (the same set; the Ball form waits on the mass-weighted space, group 7); KKT push-forward precision **dropped** on purpose (a silent solve inside an algebraic operation; ask the credible set through a solver). DESIGN §66.
- [x] 10. `LinearOperator.matrix(dense=False)` scipy bridge — **restored** as `as_scipy(form=, n_jobs=)`, a matrix-free scipy operator with the form's metric factors in `matvec`/`rmatvec` and parallel column loops, and its converse `from_scipy(domain, codomain, op, form=)`; not on `matrix()`, which means a dense array in v2. No internal consumer remains, every v1 one having its own v2 code. DESIGN §67.
- [x] 6. `random_domain_points`, the `extend` grid option — both **restored**: `Sphere.random_domain_points(count, ocean=, rng=)` by rejection against the Natural Earth coastlines the mask already loads, shared through one cached test; `extend=` on the sphere gives fields the wrap column and pole row for plotting and interchange, the transforms, quadrature and point evaluation working on the core grid unchanged. GLQ grids are a session of their own (group 7). DESIGN §68.
- [x] primal feasible-property route is norm balls only — **generalised** to quadratic level functions on both sides: the bisection engine is written in the prior's and the confidence set's own inner products (the prior's covariance as an operator, the confidence set's precision through its Cholesky factor on the data components), so an ellipsoid on either side, centred anywhere, takes the cheap route with its extremal model, inclusion norm and extent; no whitening of the problem, no factor asked of the sets (David: "just allow for more general sets and functionals"). Dispatch: both quadratic → bisection and reduced membership. DESIGN §69.
- [x] general level functions, membership side — **done**: the likelihood engine takes any differentiable convex level function on either side (a ball, an ellipsoid, a smooth sublevel set), minimising the prior's level function over the models with a given property that fit; the answer's `level_function`/`level` follow the general contract (the prior's level function at the fitting model, against the prior's level; `inclusion_norm` is the quadratic root as before); a set with a level function but no support function is known by membership alone (`route is None`). DESIGN §70.
- [x] general level functions, support side — **done**: `numerics.convex.LevelKKTSolver`, the quadratic solver's nested root find with a convex minimisation per probe, gives support values and the extremal model for any differentiable level-function sets; `route="kkt"` takes it, `auto` takes it for such sets without a support function, and the result has a maximiser on that route. Group 4 closed. DESIGN §71.

## 5. Lost knobs (§0.3)

- [x] adaptivity: `rtol=` through `random_diagonal`, `deflated_diagonal`, `JacobiPreconditioner`, `SpectralPreconditioner` — **restored** as keywords on the callers with the fixed defaults unchanged: `rtol=`/`max_samples=`/`block_size=` on the Jacobi preconditioner, the deflated diagonal and `pointwise_variance_at` (a tolerance alone selects the sampled route); `rank=None` with `rtol=`/`max_rank=`/`block_size=` on the spectral preconditioner. DESIGN §72.
- [x] `measure=` on every `testing.check_*` (David, 2026-09-17: white noise is unrealistic on a function space) — **restored** as a keyword on every check but `check_measure`, through one draw helper that validates the measure's domain. DESIGN §73.
- [x] `random_range`: `measure=` probes and `power` default 2 → 1; `random_cholesky` Nyström; `random_trace` probe type — `measure=` **restored** on the range finder and every factorisation over it (measured: on a forward operator with a decaying prior the unresolved fraction of the range the data can see fell from 0.84 to 0.16 at rank 10, while the operator's own approximation is unchanged; David remembered this); `power` **kept at 1** (a second step buys 10–15 per cent for double the applications, and the knob exists); Nyström **kept dropped** (identical to the eigen-truncation at equal output rank, within 2 per cent, and cheaper to apply); Rademacher probes **kept dropped** (no variance gain, and Gaussian white noise is what makes the trace right on a weighted space). DESIGN §74.
- [x] parallelism: `n_jobs=` on point/path evaluation, preconditioner probing, `as_multivariate_normal`, log-determinant, `support_values` — **restored** at every listed loop through `parallel_map`, serial by default: the spectral, banded, block and column-thresholded preconditioners and `sparse_approximation`, the normal-diagonal preconditioner's block probes, `log_determinant` (dense assembly and Hutchinson probes), `as_multivariate_normal`, the dense point, path and geodesic-ball operators through `basis_matrix` (the sphere splits its Legendre tables across workers), and `support_values` on every route (the general engine's parallel branch only ever ran on the dual; the closed form and bisection refused it). Uncovered and fixed: both KKT solvers trusted `fsolve`'s status and accepted a false root on a cold start; they now check the residuals (David: do not judge from toy timings what is worth parallelising). DESIGN §75.
- [x] escape hatches: `lazy_quadrature`, `incomplete=True`, `inverse_sqrt_operator` route, `to_coefficient_operator` padding, degree proposal beyond the space — `incomplete=`/`drop_tol=`/`fill_factor=` **restored** on the banded and block preconditioners through one shared factorisation; the factor route **restored** as `Ellipsoid(factor=)` (any `L` with `C = L L*`, the support value as `||L* q||`), which a measure's credible set passes on; zero-padding **restored** on `coefficient_operator`/`from_coefficient_operator` as the resolved space's operator composed with the degree transfer; the unbounded walk **restored** as `sufficient_degree(symbol, rtol=, min_degree=, max_degree=)` on every symmetric space, over the modes a degree would have, with `with_degree` on the answer standing in for v1's factories; `lazy_quadrature` **dropped** (David: fine to drop). DESIGN §76.
- [x] a derivative-only query on any `Operator` goes through `at()` and so evaluates the value too (v1 called the derivative closure alone): doubles a derivative-only query on a forward operator whose value is a PDE solve; line searches take that path. Audit row on `NonLinearOperator.derivative` — **fixed**: `derivative` calls the derivative alone, falling back to the linearisation only where a class supplies nothing else; the sum node sums the terms' derivatives and the composition node linearises the inner operator and takes the outer derivative alone (v1's counts). Line searches were already on `at()`. DESIGN §77.
- [x] `DiscrepancyPrinciple` dropped v1's `atol` and `minimum_damping`; the root finder has both but does not expose them — **restored**: `atol=` and `minimum_damping=` on `DiscrepancyPrinciple`, `MinimumNorm.for_data`/`discrepancy_search` and `misfit_search`, through new `minimum`/`maximum` fences on `monotone_root` (the walk stops at the fence and reports the range exhausted); defaults zero, so unchanged unless asked. Knobs group closed. DESIGN §78.
