## (b) Typical workflow

### pyslfp/linear_operators (the library layer)

1. **Spaces** (`sl/physics.py:353-436`): `Lebesgue(lmax, radius, grid)` or `Sobolev(lmax, order, scale, radius, grid)` load space; response space `HilbertSpaceDirectSum([field, field, field, EuclideanSpace(2)])` (SLC, displacement, gravity potential, angular-velocity change). Fields are `pyshtools.SHGrid` objects from `EarthState`.
2. **Operators are always built on the L2 spaces and lifted** (`underlying_space` → `LinearOperator(l2_dom, l2_codom, mapping, adjoint_mapping=...)` → `LinearOperator.from_formal_adjoint(sobolev_dom, sobolev_codom, l2_op)`). This is how `FingerPrintOperator` (`sl/physics.py:117-131`, matrix-free: forward = SLE solve, adjoint = generalised SLE solve), the load conversions (`sl/loads.py`), `remove_ocean_average_operator`, `centrifugal_potential_operator` (domain `EuclideanSpace(2)`) are made. Masks/averages use `space.spatial_multiplication_operator` and `space.l2_products_operator`.
3. **Observation operators** compose: tide gauges `point_evaluation_operator @ subspace_projection(0) @ fingerprint`; altimetry `point_eval @ Row[I, inclusion] @ BlockDiag[inclusion@SSH@fingerprint, I] @ Column[joint_to_load, projection(1)]` (`sl/altimetry.py:264-296`); GRACE `to_coefficient_operator(obs_degree, lmin=2) @ subspace_projection(2) @ fingerprint`. `WMBMethod` builds diagonal Love-number operators and an analytic diagonal preconditioner.

### Heathcote2026 inversion scripts (end to end)

1. **Physics**: `FingerPrintOperator(state, load_parameters=(order, scale), response_parameters=...)`; take `load_space = fp.domain`, `response_space = fp.codomain`. Forward operator = observation ∘ fingerprint ∘ (load assembly), e.g. `grace_obs_op @ fp_op @ (I + sea_level_to_load @ proj0 @ fp_op)` (`grace_inversion.py:211-217`) or the 3-field altimetry chain (`altimetry_utils.py:65-149`, model = [ice thickness, sterodynamic SL, density]).
2. **Prior**: per-field invariant measures from `point_value_scaled_sobolev_kernel_gaussian_measure(order, scale, std=)`; combined with `GaussianMeasure.from_direct_sum` or `CorrelatedInvariantGaussianMeasure.from_invariant_measures(..., corr_fn)`; masked with `affine_mapping(operator=BlockDiagonal[projections])`; **conditioned** on an exact linear constraint (mass conservation) via `AffineSubspace.from_linear_equation(...).condition_gaussian_measure(masked)` or degree-1 removal via `LinearSubspace.from_kernel(...).condition_gaussian_measure`; optionally shifted by `affine_mapping(translation=shift*prior.sample())`. Calibration uses `directional_variance`/`directional_covariance` of functionals `T.adjoint(np.ones(1))`.
3. **Noise**: `from_standard_deviation(EuclideanSpace(n), σ)` (+ a spatially correlated component pushed through `point_evaluation_operator` and added with `+`); GRACE noise = `invariant_gaussian_measure(f)` mapped to coefficient stds by `WMBMethod.load_measure_to_observation_measure` → `from_standard_deviations`.
4. **Forward problem & data**: `LinearForwardProblem(op, data_error_measure=noise)`; `model, data = fp.synthetic_model_and_data(prior)`; `data_measure = noise.affine_mapping(translation=data)`.
5. **Inversion**: `inv = LinearBayesianInversion(fp, prior)`; preconditioner = WMB analytic diagonal (GRACE) or `(1-α)*inv.surrogate_woodbury_data_preconditioner(LUSolver(galerkin=True, parallel=..), alternate_forward_operator=surr_fwd (lmax 32, 1 SLE iteration), alternate_prior_measure=surr_prior, alternate_data_error_measure=surr_noise) + α*noise.inverse_covariance`; `post = inv.model_posterior_measure(data, CGSolver(callback=ProgressCallback(), rtol=..), preconditioner=P)`; print `solver.iterations`. Joint script builds three inversions (alt-only, GRACE-only, joint via `ColumnLinearOperator` + `from_direct_sum` noise).
6. **Property push-forward**: build small property operators (regional averages, GMSL split, degree-l coefficients: `avg_op @ total_load_op`, `ColumnLinearOperator([...]) * scale` then `codomain.coordinate_projection @ ...`); `prior.affine_mapping(operator=T).with_dense_covariance(parallel=, n_jobs=)` and `post.affine_mapping(operator=T).with_dense_covariance(...)`; then `kl_divergence`, `covariance.matrix(dense=True)` for variances/trace/determinant, `directional_variance(basis_vector(i))`, `subspace_projection(i)` to get 1-D marginals.
7. **Resolution analysis** (`grace_inversion.py:416-565`): `K = inv.kalman_operator(solver, preconditioner=P)`; `R = K @ A - I`; kernels `(T @ R).adjoint(basis_vector(i))`, norms in `load_space.norm`.
8. **Spatial diagnostics**: `post.expectation`, `post.samples(n, parallel=, n_jobs=)` → pointwise std via `space.subtract/vector_multiply/axpy/vector_sqrt`; covariance maps via `post.covariance(test_vec)` with `test_vec[i] = space.dirac_representation(pt)` or `measure.two_point_covariance(pt)`.
9. **Plotting**: `sl.plot(SHGrid, ax=, colorbar_kwargs=..., gridlines_kwargs=...)`, `plot_points(points, data=...)`, `inf.plot_1d_distributions`, `inf.plot_corner_distributions`.

### The v2 shape of the same workflow
`Sphere` spaces → `lift_formal_adjoint`/`multiplication_operator`/`l2_products_operator`/`point_evaluation_operator`/`coefficient_operator` → `LinearForwardProblem(A, error=)` (+ `from_direct_sum` for joint) → priors from `sobolev_measure`/`heat_measure`/`invariant_measure`/`correlated_measure_from_correlations`/`from_product` → `est = LinearGaussianInversion(problem, prior, solver=CGSolver(...).with_preconditioner(WoodburyPreconditioner.from_normal(est.surrogate(...))))` → `post = est(data)`; `est.gain`; `est.push_forward(T)(data)` for properties; `plotting.plot/plot_points/plot_densities/plot_corner`. Structurally the v2 inference API covers steps 4–8; the blocking problems are in the operator-construction layer and in samplability/parallelism.

## (c) Prioritised gaps that would block porting pyslfp

**Blocking (must be resolved before any port is possible)**

1. **Vector type and grid**: v2 sphere vectors are `(n, 2n)` DH2 numpy arrays; pyslfp is built on `pyshtools.SHGrid` with default `grid="DH"` (sampling 1) throughout `EarthState`, `LinearSeaLevelEquation`, masks and plotting. Porting needs either an `SHGrid`-aware sphere space in v2 (or `compat.py`-style adapter, `v2/compat.py:1-60`, which is the intended transition route) or a conversion layer in pyslfp plus forcing DH2 everywhere.
2. **`lift_formal_adjoint` only accepts `SymmetricSpace` domain and codomain** (`v2/symmetric_space/base.py:1206-1241`). pyslfp lifts operators whose codomain is a `DirectSum` (`FingerPrintOperator`, `sl/physics.py:129`) and whose domain is `EuclideanSpace(2)` (`centrifugal_potential_operator`, `sl/physics.py:480`). v1 `from_formal_adjoint` handles direct sums recursively and identity-metric spaces. v2 needs a generalisation to any `CoordinateSpace`/`DirectSum` (using `apply_gram`/`solve_gram` blockwise).
3. **Conditioned Gaussians are not samplable in v2** (`GaussianMeasure.condition`, `gaussian.py:814-862`, returns covariance only). pyslfp conditions every prior (mass conservation, degree-1 removal), then samples it (`synthetic_model_and_data`, `prior_shift`, MC validation, and — through `_prior_and_noise_can_be_drawn` — posterior RTO samples for `--std-samples`). Workaround exists (`LinearGaussianInversion(LinearForwardProblem(constraint), prior)(value)`), but `condition` should carry the RTO sampler, and `AffineSubspace/LinearSubspace` should regain `condition_gaussian_measure`.
4. **Point convention**: `(colatitude, longitude)` radians in v2 vs `(latitude, longitude)` degrees in v1/pyslfp for `point_evaluation_operator`, `dirac`, `two_point_covariance`, `plot_points`, `stations`. Every point list in pyslfp (`read_gloss_tide_gauge_data`, `ocean_altimetry_points`, hard-coded covariance-map points) must be converted; risk of silent errors.

**High (needed for the large Heathcote2026 runs to be feasible / equivalent)**

5. **No process parallelism anywhere in v2** (`parallel=`/`n_jobs=` grep returns nothing): affects `with_dense_covariance` (property posteriors: each column = one CG solve with the SLE inside), `samples(n)` (posterior RTO draws), dense assembly for the Woodbury inner solve (`LUSolver(parallel=...)` on a ~3k-dim surrogate normal operator), `extract_diagonal`. These are the call sites the scripts expose `--parallel/--max-jobs` for.
6. **Solve diagnostics are lost through the estimator**: `est(data)` discards `SolveResult`; there is no `solver.iterations`, no `ProgressCallback`. Needs either a `SolveResult`-returning path on `GaussianEstimator`/`LinearGaussianInversion` (e.g. `est.solve(data)` or a `last_result`), or at least a stock progress callback.
7. **`from_product` drops precisions** (`gaussian.py:194-217`): the surrogate prior for the Woodbury data form is a product of invariant measures that each have a diagonal precision; v2 will fall back to a CG inversion of Q inside the preconditioner. Should build a `BlockDiagonalLinearOperator` precision when every factor has one. Similarly `measure + measure` loses precision, which also breaks `problem.chi_squared` on the white+correlated altimetry noise.
8. **`op.check(..., domain_measure=, codomain_measure=)` has no equivalent**: `testing.check_operator` draws `space.random()`; the fingerprint adjoint test needs smooth (heat-kernel) random fields for the SLE iteration to converge. Add optional `domain_measure`/`codomain_measure` (or a `sampler`) to `check_operator`.

**Medium (real work, but local)**

9. **Plotting API regression**: v2 `plot` lacks `projection=`, `contour`, `contour_lines`, `rivers`, `borders`, `map_extent`, `colorbar_kwargs` (horizontal colourbars are used in every H26 figure), `gridlines_kwargs`; `plot_points` lacks `data=` colouring with colourbar and `coasts/gridlines` toggles. `plot_densities`/`plot_corner` lack `title`. `pyslfp/plot.py` is a thin wrapper over the v1 signatures, so this is a mechanical but sizeable rewrite.
10. **Missing helpers**: `from_coefficient_operator` (WMB inverse map), `GaussianMeasure.from_standard_deviations` (per-component), `ProgressCallback`, `CorrelatedInvariant...from_invariant_measures` accepting a callable of the eigenvalue (v2 wants a `(dim,n,n)` array).
11. **Coefficient ordering within a degree differs** (v1 pyshtools `0,1..l,−1..−l`; v2 `cos 0..l, sin 1..l`): degree blocks stay contiguous so `WMBMethod` index arithmetic survives, but component labels in `grace_inversion.py:372-381` and any downstream consumer of the coefficient vector change.
12. **Name/semantics traps** to audit during a port: `space.zero` → `zero()`; `space.scale` is now a method (Sobolev length is `length_scale`); v1 `multiply(scalar, x)` → v2 `scale`, while v2 `multiply` is pointwise; `vector_multiply/vector_sqrt` → `multiply/sqrt` with band-limit truncation; `coordinate_projection` → method; direct-sum vectors are tuples; `heat_kernel_gaussian_measure(scale)` → `heat_measure(scale**2)`; `order_inclusion_operator(order)` → takes a space; `chi_squared_test(level, m, d)` → `(m, d, level=)`; `CholeskySolver` requires an explicit `POSITIVE_DEFINITE` claim on `B @ B.adjoint` (`sl/spatial.py:667`); `Lebesgue`/`Sobolev` are factory functions so all `isinstance` checks in `sl/utils.py` must become `isinstance(x, Sphere)` + `order`.

**Low / already covered well by v2**

- The inference core maps cleanly: `LinearForwardProblem`, `synthetic_model_and_data`, `LinearGaussianInversion` (+`from_direct_sum` for joint problems), `gain`, `normal_operator`, `surrogate` + `WoodburyPreconditioner.from_normal`, operator-valued preconditioner blending, `push_forward` for property posteriors (with samplers carried through), `kl_divergence` (spectral/dense/stochastic), `directional_variance/covariance`, `two_point_covariance`.
- Matrix-free by default: `point_evaluation_operator` (NUFFT fast path), `coefficient_operator` (selection), `multiplication_operator`, `l2_products_operator`, `DiagonalLinearOperator` — these are improvements over v1 for the large altimetry point sets pyslfp uses.
- Prior constructors (`sobolev_measure`/`heat_measure`/`invariant_measure` with `pointwise_std`, `correlated_measure_from_correlations`) use the same spectral convention as v1's invariant measures, so the noise-amplitude solver in `grace_utils.resolve_noise_amplitude` remains valid.
