## 2. Bugs and regressions found now

Verified:
1. **`with_order` discards the D-3 geometry class** (`symmetric_space/sphere.py:1573-1594` returns `Sphere(...)`). `Sobolev(32,2,.2).with_order(0.0)` is not a `Lebesgue`; `type(x).__name__ == "Sphere"`. Same for `with_order(1.0)` on a `Sobolev`. D-3's stated reason ("so `isinstance` works and the class name names the geometry") fails for every derived space. Repro: `K/pyslfp_shape.py` line A. Fix: `type(self)(...)` where the subclass signature allows, else a `Lebesgue`/`Sobolev` choice on `order == 0`.
2. **`plot_points` cannot colour by data** (`plotting/sphere.py:239`, `c=color` hard-coded): `plot_points(X, pts, c=vals)` → `TypeError: got multiple values for keyword argument 'c'`; `data=vals` → `ValueError`. v1 `sphere.plot_points(points, data=…)` with a colourbar is what pyslfp's altimetry scatter uses (U H).
3. **Catalogue row L416 is false** (`deflated_pointwise_variance` "Ported"; absent). `test_code_practice.py:217` misses it because the row's backticked names are not dotted.
4. **`_to_mfem` docstring** (`backends/mfem.py:466-472`) gives a false reason: the CSR list constructor *is* bound; it is unusable because MFEM frees numpy's buffers (`K/mfem_csr.py`: `double free or corruption` on exit in every mode). Say that instead, or somebody will "fix" it into a segfault.
5. **Export holes** (K Must-3 leftovers) and the `Functional` rule-3 violation (Should-13): `numerics` lacks `weighted_chi2_*`, `resolve_solver`; `inference` lacks `FactoredNormalOperator`; `algebra` lacks `HilbertModule`, `require_module`, `MassWeightedSpace`; `mfem.__all__` lacks `white_noise_load`, `matern_measure`.
6. **`norm(x)` transforms `x` twice** (`spaces.py:772` `DiagonalMetricSpace.inner_product` → `to_components` on both arguments; `norm` = `inner_product(x, x)`): `K/transforms.py`-style count gives 2 expansions per norm on `Sphere`, 1 needed. Every Krylov/Gram–Schmidt norm pays it.

Unverified suspicions:
- `test_the_stochastic_route_agrees_with_the_dense_one` asks `random_trace` for up to 4000 probes at `rtol=1e-10` on a toy problem (`test_inference.py:557-585`); the test is large by choice, but 6.5 `eigh_tridiagonal` calls per probe (`functional_calculus.py:200-260`, convergence checked by a full recombination at every step) is library overhead worth ~30% of it.
- Coefficient ordering within a degree (U 11) not re-checked; assume unchanged.

## 3. Optimisations, ranked (gain × confidence)

1. **`orthonormal_basis`/`_orthogonalise_against` on a `CoordinateSpace`** (`algebra/spaces.py:215-262`, `_orthogonalise_against` at `:241`; used by `random_range` `numerics/randomised.py:151-184` and `_power_iterate` `:95-98`, hence `random_eig`, `SpectralPreconditioner`, `low_rank_surrogate`, `LowRank*`, `deflated_diagonal`). Every inner product/norm re-expands both grids: `random_range(rank=50)` on `Sobolev(128)`: **17 916 expansions, 54 s**; floor ≈ 300 (one expand + one synth per operator application). `orthonormal_basis(50 vectors)` alone: 2650 expansions, 7.44 s, versus **Cholesky-QR in components** (transform each vector once, `apply_gram` columnwise, `cholesky(CᵀGC)`): 100 transforms, **0.31 s, 24×**; whole `random_range` estimated 54 s → ~2 s (**~25×**). At lmax 64/rank 30: 2.86 s → ~0.1 s. Risk: low — add a `CoordinateSpace` fast path (components, `apply_gram`, block Gram–Schmidt or Cholesky-QR with one re-orthogonalisation), keep the coordinate-free path for `OpaqueSpace`; `test_randomised`/`test_coordinate_free` already pin both. (`K/rr.py`)
2. **`plot_corner` KDE** (`plotting/distributions.py:532-536`): `gaussian_kde(20000 draws)` on a 160×160 grid = 3 s per panel, **8.9 of 12.2 s** in ex26; `_density` (`:180`) same at 2000×20000. `histogram2d` + `gaussian_filter` with the KDE bandwidth: **0.005 s (>500×)**, max relative error 6% of the peak (subsampling to 4000 draws: 0.24 s, 11%). Risk: contour levels move by a few %; acceptable for a figure. (`K/kde.py`)
3. **Dense path/ball operators** (`symmetric_space/base.py:1965-2010 _path_operator`, `dense=True` branch `weights.matrix(form="components") @ self.basis_matrix(nodes)`): `_weight_operator` (`:2158`) is a `from_callables` closure, so the 960×15360 weight matrix is extracted by 960 applications (0.28 s) then densely multiplied (1.59 s) although it has 16 nonzeros per row. Sparse `W @ B`: **0.018 s (90×)**, identical to 2e-16. Plus per-node Python in `geodesic_quadrature` (`sphere.py:1107-1150`, 0.40 s for 15 360 nodes) → vectorised over paths 0.014 s (30×). ex21 `path_average_operator(dense=True)`: 2.70 s → ~0.5 s (then `basis_matrix` dominates). Fix: return `LinearOperator.from_matrix(..., csr, form="components")` from `_weight_operator` and multiply `stored_matrix`; `geodesic_ball_average_operator` (`:2021`) shares the bug. Risk: nil. (`K/path_dense.py`)
4. **Import time**: lazy `scipy.stats.chi2`/`scipy.integrate.quad`/`scipy.optimize.brentq` in `numerics/quadratic_forms.py:19-21` and `inference/problem.py:20` — **0.43 → ~0.25 s (40%)**, 3 runs. Risk: nil.
5. **Correlated Gaussian on a direct sum of spheres** (`Sphere.correlated_measure*` → `BlockLinearOperator` of `DiagonalLinearOperator`s): covariance application 4 expand + 6 synth where 2 + 2 is the floor (each block does its own `to_components`/`from_components`, `algebra/diagonal.py:100`); `sample()` 4 + 8 vs floor 0 + 2. A single `sobolev_measure` sample costs 1 expand + 2 synth (white noise synthesised, then re-expanded by the factor) vs floor 1. Estimated 2.5× on prior applications inside CG for pyslfp's `(Dyn, Rho)` anti-correlated prior, 6× on prior sampling. Fix: a spectral block operator that transforms each field once and applies the `(dim, n, n)` array in components; `white_noise_components`-based sampling for diagonal factors. Risk: medium (new operator class; adjoint must be tested on a dense Gram). (`K/transforms.py`)
6. **`norm` and Lebesgue inner products** (`spaces.py:772`): `norm` should expand once (2× per norm); on `Lebesgue` (order 0) the DH quadrature (`DHaj`, exact to degree 2·lmax+1 for a product of two band-limited fields) gives the inner product with **0 transforms** instead of 2. Gain: 2× on every norm in Krylov loops on spheres; more for L2 checks. Risk: low; verify against the current value on `make_dense_metric_space` for the generic path.
7. **`plot_paths`** (`plotting/sphere.py:245-290`): one `ax.plot` per path piece (1294 calls, 3.9 s in ex21, cartopy re-projects each). A single `LineCollection` (or one `ax.plot` with NaN breaks) is ~10–20× cheaper; unmeasured. Risk: nil.
8. **Lanczos convergence check** (`functional_calculus.py:200-260`): `eigh_tridiagonal` at every step (104 000 calls for 16 000 probes, 2.9 of 9.5 s). Check every k steps or use the last-column bound. ~30% of stochastic `log_determinant`/`random_trace`; matters at pyslfp scale only if the evidence route is used. Risk: low.

Below the 10% bar / not proposed: `_to_mfem` per-entry loop (16 ms per 33k nnz, once per operator); `random_trace` Python overhead per probe.
